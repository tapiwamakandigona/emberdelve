# v0.108.0 — The Proven Rules

The weekly's rules are good tests, but the calendar deals them: if
Cold Camps is this week's rule, Flint Week is a month away. Two new
Provings keep the rules standing, so they can be taken deliberately:

- **The Flint Proving** — the Kindler, normal, every die a d4
  (seed 6, bot-win proven with the rule applied).
- **The Cold Proving** — the Warden, normal, no rests on the map
  (seed 2, bot-win proven with the rule applied).

The card states the rule in its meta line, plainly. A modded proving
shows **no Delve Code** — a code cannot carry rules, and one that
replayed the run without them would be a lie (the v0.103.0 refusal,
applied again).

Also fixed on the way: a latent honesty bug in the clear-match. It
compared seed + delver + difficulty + rung but ignored rules, so a
modded run of an unmodded proving's exact seed would have cleared
it. Unreachable before mutator provings existed; load-bearing now.
The mark means the exact delve — rules included — was walked.

## Technical

- ProvingDef gains `mutators` (default const []); 12 provings.
- Controller clear-match adds `setEquals(sim.mutators,
  p.mutators.toSet())`.
- provings_screen: startRun passes p.mutators; rule names join the
  meta line; code suppressed on modded cards.
- Winnability proof now walks each proving's ACTUAL rules
  (playRun gains `mutators: p.mutators`).
- test/proven_rules_test.dart (4): rule legality + ash_summit stays
  last, modded win clears, unmodded run of the same seed does not,
  modded run of first_flame's seed does not.
- Plates: modded card at 360/320 — rule in meta line, no code,
  neighbor card keeps its code.
