# v0.89.0 — The Counted Rest

At a fork, players should weigh options, not do arithmetic.

The rest fire asked for three derivations before every choice: 30% of my
max HP, minus the overheal cap, plus whatever my rest relics add. Slay the
Spire prints the literal heal on its rest button for exactly this reason.
Now ours does too:

- `Rest — heal 9 HP (21 to 30)` — the exact amount and where it lands.
- The overheal cap is shown honestly: at 28 of 30 the button says heal 2.
- Bedroll (+4) and Hearth Kettle (+6) are counted in — relics bought for
  this moment finally show their worth at it.
- At full HP the button stays 'Move on — fully rested'; a zero-heal offer
  is never printed.

## Honesty rules

- The number comes from `restHealPreview(Sim)`, a pure no-mutation mirror
  of the sim's own rest arithmetic living beside `runRest` — one source of
  truth, so the button can never lie. A parity test proves the promise
  equals the heal the command then performs.
- No percentage alongside the number: two encodings of one fact is noise.
- No breakdown ledger on the button; relic text already documents bonuses.

## Technical

- `restHealPreview` in sim/run_layer.dart; rest_screen prints it.
  Non-breaking spaces bind '(21 to 30)' so narrow screens break before the
  parenthesis, never inside it; 'to' instead of an arrow because the
  display face has no U+2192 and drew tofu (caught on plates). Tests +4
  (`test/rest_preview_test.dart`; new pinned seed: kindler easy 3 = bot
  walk reaches a rest fire at 3/30 HP). Plate-critiqued at 360x640 and
  320x568 (longest wording, Bedroll stacked). Zero assets, zero sim
  movement — the preview is a read-only function addition.
