# v0.122.0 — The Spoken Delve

An accessibility audit found the run's choice surfaces were pure
paint to a screen reader — combat's tray spoke (v0.44.0), but a
blind player could fight and never PICK. Every choice now speaks:

- **Reward cards**: 'Take the Ember Die, a d6, the recommended
  pick' — and 'A reward card, still face down' before the flip
  (a button only once it can actually be taken).
- **Boon cards**: one spoken button per card — name, recommendation,
  effects ('Keen Start, the recommended pick. d6 die').
- **The temper sheet**: dice ('Die 1, Flint Shard, chosen'), faces
  ('Face 3'), and runes (name + blurb, chosen state) all speak.
- **The shop**: the buy button said a bare number ('36'). It now
  names the deed — 'Buy Ash Aegis for 36 gold' — or the shortfall
  ('Ash Aegis, 36 gold, not enough gold').
- Zero visual change; zero sim surface; zero re-anchor.

## Technical

- EmberButton grew `semanticLabel` (overrides the drawn label in
  its existing merged Semantics node). LESSON: do NOT wrap an
  EmberButton in an outer Semantics(excludeSemantics) — that
  swallows its onTap action and the node merges into the panel;
  override inside the widget that owns the action.
- test/spoken_delve_test.dart (4): reward/boon/shop labels pinned
  via ensureSemantics + bySemanticsLabel against the same defs the
  paint uses; honesty sweep over the label vocabulary.
- Boon offers idiom for tests: startRun(boons: true) — the restart
  flow's opener; offers read from state['boons'], reward offers
  from state['offers'].
