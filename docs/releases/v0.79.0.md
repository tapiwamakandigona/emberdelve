# v0.79.0 — The Settled Score

The run that finally fells the old foe now says so.

v0.78.0 named the enemy that has ended more of your delves than any other;
this release closes the loop. When a run fells the reigning old foe, the
summary carries one gold line — 'The score with the Wick Widow is settled.'
Once per foe, EVER: the score never reopens when it fells you again, because
a payoff that resets is not a payoff, it is a treadmill.

## Honesty rules

- No embers, no unlock, no badge rides on settling — the felling is the
  reward, and paying for it would invite farming the moment.
- The line fires only for the foe that held the title when you felled it.
- A settled score stays settled (`meta.settledFoes`, persisted, cloud-merged
  as a union). No see-saw, no manufactured recurring obligation.

## Technical

- `oldFoe` moved from the ledger to `lib/meta/meta.dart` (the controller
  needs it; UI already imports meta). Same semantics, same tests.
- Controller transient `pendingSettledFoe`, set at the felled-record site;
  survives mid-run resume via the autosave side channel (`settled_foe`);
  cleared on new run and return to title.
- Summary line key `settled-score`; helper `settledScoreLine` never names a
  retired id. Tests +4 (`test/settled_score_test.dart`); the flaky teardown
  in `test/new_song_test.dart` hardened with the standard delete-retry loop.
- Zero new assets, zero sim movement.
