# v0.26.0 scouting — tablet / large-screen support (NOT yet committed to)

Scouting notes 2026-08-16, written during the v0.25.0 CI wait. No decision
yet; this records the ground truth so the next scoping pass starts warm.

## Current state

- `main.dart` hard-locks portraitUp/portraitDown (SystemChrome, line ~30).
- Screens are portrait compositions; several already use
  MediaQuery/LayoutBuilder (stage, combat, map, reward, summary, title,
  tutorial overlay, temper sheet) — so per-screen adaptation points exist.
- Overflow discipline only sweeps portrait phone sizes (320×568 → 412×915
  @1.3x). No tablet sizes in any gate today.

## Why it might matter

- Sideload audiences (GitHub releases) skew toward tablets/emulators/
  Chromebooks more than Play audiences do.
- Google large-screen quality guidelines are a real studio priority and a
  future Play featuring requirement — but Play is dormant per owner
  directive, so that part is not urgent.

## Honest scope options (one release each)

1. **Tablet-portrait quality pass** (small): max-width clamp + centered
   column on menu-family screens; combat/map untouched (they scale). Add
   800×1280 and 1600×2560@2x to the overflow sweep. Low risk.
2. **Landscape menus only** (medium): unlock landscape for title/settings/
   ledger/news/summary; combat+map force portrait via per-route
   OrientationBuilder guard. Mixed-orientation apps are fiddly; needs a
   clear in-game rationale.
3. **Full landscape** (large): every screen recomposed; combat diorama and
   one-thumb reach both need redesign. Competitor Slice & Dice ships both
   orientations. Not one clean release — do not attempt as a single drop.

## Recommendation for next scoping pass

Option 1 first (pure quality, testable, zero orientation risk), and only
then judge whether landscape demand is real (GitHub issue feedback, Reddit
comments) before paying for option 2/3.
