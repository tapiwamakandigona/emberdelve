# v0.70.0 lead scout — The Pictured Card (the delver on the Delver's Card)

Date: 2026-08-26. Scout ran after v0.69.0 (The Standing Delver) closed.

## The lead

The Delver's Card — the ONLY artifact that leaves the game — still shows the
generic trophy/flame where the delver should stand. v0.69.0 fixed this on
the summary; the shared card is the same gap with higher stakes: every card
posted to a group chat is organic marketing, and a personalized delver (own
dye, own title already in the name line) makes the card unmistakably
SOMEONE'S run instead of a template. Costs one widget swap.

## Shape

- `DelverCardFacts` gains `charId` + `dyeId` (the card stays a pure function
  of facts — tests can pin both). `fromController`: `dyeId =
  c.meta.dyeFor(charId)`. `fromRecord` gains an optional `MetaState? meta`
  and resolves the delver's CURRENT coat (portraiture, not history — dyes
  were never banked per run, and the picker shows the same current coat).
- `DelverCard`: the 40dp trophy/flame Icon becomes
  `SpriteView(charId, height: 44, animate: false, dye: Art.dyeFilter(dyeId))`
  — static frame, pixel-crisp at the 3x export (SpriteView paints with
  nearest-neighbor).
- Loss cards keep full opacity: the exported artifact is a poster, not the
  live summary moment — a dimmed sprite reads as a rendering bug in a chat.
- Export-race note: the card is displayed in the share sheet BEFORE the
  boundary is exported, so the sprite is decoded by tap time; the existing
  clipboard fallback covers any failure.

## Rejected alternatives

- Banking the dye worn at run time into run records (true history): rejected
  — a new save key for pure portraiture; the epithet precedent banked
  'worn-at-the-time' because titles are NARRATIVE (the epitaph quotes them);
  a coat is paint, and current paint is what every other surface shows.
- Weapon beside the sprite: rejected — the 340x480 canvas is dense; the
  sprite alone is the identity note.
