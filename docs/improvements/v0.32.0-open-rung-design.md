# v0.32.0 — "The Open Rung" (retention hook #7: mastery ladder surfacing)

## Problem

The Ascension ladder is the game's whole mastery arc for Forge owners, yet the
only place it exists in the UI is a static number in the Ledger and a +/-
stepper on the character screen. Winning a run at your best rung silently
unlocks the next one (`_bankRun`, controller.dart ~L959-965) — the single most
earned moment in the game announces nothing. Research doc hook #7: "Ascension
already exists; surface 'next ascension' on win."

## Design

One line on the win summary, shown ONLY when THIS run's win actually raised
`bestAscension` (i.e. the player won at their frontier rung):

> "Rung N of the Ascension now stands open."

where N = the new `bestAscension`. Styling: same micro/textDim treatment as
the firsts line. No button, no price talk, no nudge to buy — this line can
only ever appear for a player who already owns the Forge and just EARNED the
rung (clampRunParams caps free profiles at rung 0, and a rung-0 win only mints
rung 1 for Forge owners... note: bestAscension moves for any win at
asc >= bestAscension, including free-profile rung-0 first wins — see Gating).

## Gating (§Ethics review)

`meta.bestAscension` advances on ANY win where `asc >= bestAscension` — a free
profile's first win moves it 0 → 1. But a free profile cannot USE rung 1
(maxAscensionFor clamps to 0), so announcing "rung 1 stands open" to a free
player would be a lie-by-implication and a soft upsell after a win. Charter
says no.

Rule: show the line only when `meta.forgeUnlocked && rungOpened != null`.
For Forge owners it is pure fact: the stepper's `max unlocked` really did just
grow. Free players see nothing (their mastery beat is the Normal nudge,
v0.29.0, and rank marks).

## Mechanism

- Controller: new announcement field `int? pendingRungOpened` mirroring
  `pendingRankUp`'s lifecycle exactly:
  - cleared in `startRun` (same block as pendingRankUp = null, ~L418)
  - set in `_bankRun` inside the existing `asc >= meta.bestAscension` win
    branch, AFTER the clamp: only when the clamped new value differs from the
    old (a win at rung 20 re-clamps to 20 → no announcement, matching the
    existing "no rung 21" comment)
  - derived announcement state — NOT persisted, NOT in the save blob (same
    contract as pendingRankUp; a resume mid-run never had it, and a resumed
    summary is impossible: banking is atomic with reaching summary)
- Summary: after the codex-pull block, before the trial chip:
  `if (c.pendingRungOpened != null && c.meta.forgeUnlocked)` render micro line
  key `rung-open-line`.
- Sim untouched. No new persistence. No news-feed coupling beyond the release
  news entry.

## Tests

- Controller: win at frontier rung with forgeUnlocked=true → pendingRungOpened
  == new bestAscension; win below frontier → null; loss → null; startRun
  clears it; rung-20 win → null (clamp).
- Widget: Forge-owner frontier win summary shows `rung-open-line` with exact
  text; free-profile win (seed 1 easy) does NOT show it even though
  bestAscension moved 0→1.
- Plates: tool/rung_open_visual_test.dart (nudge template), small/phone/tablet.
