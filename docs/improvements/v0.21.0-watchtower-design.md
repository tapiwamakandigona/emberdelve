# v0.21.0 "The Watchtower" — update awareness for GitHub-only distribution

## Problem

In GitHub-only mode there is no store, so there is no update channel:
a player who sideloads v0.18.0 has no way to learn v0.21.0 exists.
Every improvement we ship reaches only new downloaders. Update awareness
is the single highest-leverage retention gap in this distribution mode.

## Constraints (§Ethics, in this order)

1. No nagging, no badges, no auto-download, no pressure language.
2. Network calls must be explicit or opt-in; the game is offline-first
   and stays that way. Precedent: Daily Delve reminder — opt-in, OFF by
   default, neutral-fact copy.
3. Zero new dependencies (dart:io HttpClient; releases API is one GET).

## Design

Two pieces, both in Settings, sim untouched:

1. **"Check for updates" button** (manual, always available): one GET to
   `https://api.github.com/repos/tapiwamakandigona/emberdelve/releases/latest`,
   compare `tag_name` to `currentAppVersion` (news.dart — already pinned
   to pubspec by test). Result shown inline, neutral copy:
   - newer: "v0.21.0 is out — you have v0.20.0." + "Open releases page"
     (external browser; no in-app download).
   - current: "You're on the latest release."
   - offline/API error: "Couldn't reach the watchtower. Try later."
2. **Opt-in launch check** (`_EmberToggle`, OFF by default, meta field
   `updateCheckEnabled`): at most once per app launch, silent unless a
   newer tag exists; then ONE dismissible line on the title screen
   ("v0.21.0 is available"), tap → Settings. Never a modal, never a
   badge count, dismiss is remembered per-version (`lastSeenUpdateTag`).

## Details

- Version compare: parse `major.minor.patch` ints from tag (strip `v`);
  malformed tag => treat as not-newer (fail quiet). No prerelease logic —
  we don't publish prereleases on this repo.
- `UpdateService` in lib/meta/update_service.dart, injectable HTTP
  fetcher for tests (no network in test suite; fixture JSON).
- Meta: `updateCheckEnabled` (bool, default false), `lastSeenUpdateTag`
  (String?, null default) — both tolerant on old saves (fromJson `??`).
- Android manifest already has INTERNET (Firebase/billing).
- Gate: unit tests for version compare + service behavior on fixture
  responses (newer / same / older / garbage / HTTP 500), settings
  overflow sweep unchanged, semantics gate covers the new toggle+button
  automatically.

## Not in scope

- Auto-download/self-update APK (security theater risk, and Android
  sideload UX handles it).
- Any server of ours; GitHub's public API is the only endpoint.
- Play-mode behavior: when store distribution resumes, the store updates
  and this stays harmless (it just reports the tag).
