# v0.51.0 — "The Obituary" design (run-end storytelling)

Chosen from `v0.51.0-lead-scout.md` candidate #1. One improvement, one release
(DEMAND gate). Zero sim changes — presentation + additive meta only, so
goldens, sweeps, and pinned seeds are untouched by construction.

## What ships

A short, honest, generated epitaph paragraph on the run summary screen — the
run's story told back to the player in 2–3 sentences — plus a plain-text
"Copy delve story" share button, and the killer's name remembered in the
Ledger's Recent Delves rows.

Example (loss):
> **Here fell Wren the Kindler.** She delved 11 of 15 floors on Normal,
> six of them without a scratch, before the Cinder Tyrant ended the run.
> First felling this delve: Ash Hound.

Example (win):
> **Wren the Kindler came back up.** Fifteen floors on Normal, four of them
> clean, the Bellows King felled at the bottom. 212 embers banked.

## Why (hook rationale, from scout doc)

Roguelite retention research and our own reviews ("I still don't understand
what's a delve but it doesn't matter") say players bond with RUNS, not stats.
A death that gets a sentence is a death that gets retold — the cheapest
shareable we can build, and it composts losses into narrative instead of
frustration (§Ethics: no FOMO, no purchase prompt near a loss).

## Mechanics — all verified in code 2026-08-25

1. **Killer capture.** `_runRecord` (controller.dart ~L1227) gains additive
   `if (result == 'lost' && killerId != null) 'killed_by': killerId`. At
   `_bankRun` time the terminal sim still holds `sim.enemy` on `run_lost`
   (phase set _terminal L222 keeps sim). Old records simply lack the key —
   renderers must null-check. VERIFIED: `cloud_merge.dart` L77 copies
   `runHistory` wholesale (`fresh.runHistory.map(Map.from)`), so the new key
   round-trips through cloud saves with no merge change.
2. **Story text.** New pure function `delveStory(GameController c)` (or a
   small `lib/game/obituary.dart` with a testable
   `obituaryText({character, difficulty, floor, floors, outcome, cleanFloors,
   killerName, firstFelled, embers, short, ascension})` core). Inputs all
   exist today:
   - clean/hurt per floor: `RunTrace.marks` (run_trace.dart L25+),
     autosave-safe via toJson.
   - first fellings: summary_screen.dart `_firstsLine` logic (~L788),
     reuse `c.runFirstFelled`.
   - killer name: `enemies[killerId]?.name` (same live-resolve convention as
     `_firstsLine`).
   - floors/floor/embers/difficulty/ascension/short: `_runRecord` fields.
3. **Summary UI.** Panel paragraph above the share buttons in
   summary_screen.dart (~L520 block). "Copy delve story" button follows the
   `copy-daily-result` pattern exactly (Clipboard.setData + announce,
   ValueKey('copy-delve-story')). Story text key ValueKey('delve-story').
4. **Ledger.** `_historyRow` (ledger_screen.dart) appends
   "· felled by {name}" when `killed_by` present and resolvable. Old rows
   render unchanged.
5. **Epithet/character naming.** Use the character's display name + selected
   epithet if any (`meta.selectedEpithet`) — "Wren the Kindler, Ashwalker".
   Fall back to plain character name. No new strings persisted.

## Copy rules (§Ethics)

- Honest numbers only — every figure comes from the finished run.
- Losses are dignified, never mocking; wins are proud, never braggy toward
  others. No streak language, no "come back tomorrow".
- Deterministic given the run record + trace: same run, same story (template
  selection keyed on runSeed so tests can pin exact strings).

## Test plan

- Unit: obituaryText golden strings for win / loss / short-road / A>0 /
  no-killer (abandoned) / legacy record without killed_by.
- Widget: kindler easy seed 18 loss (pinned) shows ValueKey('delve-story')
  containing the killer's name; seed 1 win shows the win form; copy button
  copies. Reuse playOut() bot loop from waymarks_test.dart.
- Ledger widget: history row with and without killed_by.
- Full suite + analyze; sweeps NOT required (no sim change) per DEMAND gates,
  but run the kindler pin file as a canary.
- Plates: summary win + summary loss + ledger at the 4 standard sizes.

## Risks

- Template text overflow on 320×570 — keep story ≤ ~3 lines at micro/label
  size; overflow sweep gate applies (UI change).
- `sim.enemy` may be null on non-combat deaths (event/hazard chip damage?) —
  VERIFY during build whether run_lost can occur outside combat; if yes,
  killed_by stays absent and the loss template degrades to "the delve ended
  on floor N" (no invented killer).
- News entry + currentAppVersion bump as usual; achievements: none (story is
  recognition-free by design).
