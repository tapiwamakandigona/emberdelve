# v0.19.0 "The Spoken Flame" — TalkBack pass, gated

Studio lesson: accessibility is retention nobody measures — screen-reader
players who bounce off an unlabeled button never file a bug, they just
leave. Roguelites are actually a good fit for blind play (turn-based, no
timing pressure) IF information parity holds: everything the eye gets,
the ear must get.

## Audit method (not vibes)

New gate `test/semantics_probe_test.dart`: walks the same phase route as
the overflow probe with semantics enabled and fails on any tappable
semantics node with no spoken text. **Vacuity-guarded**: the test also
fails unless it saw >30 tappable nodes (run walk) / >10 (meta screens).
The guard paid for itself immediately — the first draft read
`rootPipelineOwner.semanticsOwner` (always null in tests) and passed
green on an audit of zero nodes. Same failure shape as the verify.py
lesson from v0.17.0: **a checker that finds nothing must prove it looked.**

## What the audit found (prior coverage was already good)

EmberButton, DieChip, HP bars, resource pips, intent badges, summary and
top bar all spoke already (built over v0.3–v0.16). Real gaps:

1. **Map medallions** — the game's main navigation was silent: pure
   CustomPaint + icon, no label. Now speak "Elite fight, floor 3,
   reachable" / "you are here" / "out of reach".
2. **Settings ember toggles** — drawn coal replaces Material Switch, so
   TalkBack heard bare "double tap to activate". Now announce their row
   label + toggled state (Haptics, analytics, reminder, music/sfx mute).

## Beyond labels: events a sighted player sees happen

3. **Flash toasts are a live region** — heals, forges, surge rerolls,
   invalid-move reasons are spoken when they appear (Android-recommended
   pattern; no focus steal).
4. **Phase announcements** — `SemanticsService.sendAnnouncement` on phase
   transitions: "The delve map", "Combat: <enemy> with N HP", "Choose a
   reward", "Victory. The run is won". Once per transition, silent
   no-op without a screen reader.

## Not in scope (recorded for later)

- Per-die roll announcements during the tumble (candidate: announce the
  turn's roll summary once settled; needs on-device TalkBack testing to
  tune verbosity — too chatty is as bad as silent).
- Traversal ORDER tuning (sort keys) — default order follows layout and
  reads acceptably in tests; revisit with a real device.
- iOS VoiceOver — no iOS build target yet.
