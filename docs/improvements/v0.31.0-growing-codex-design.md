# v0.31.0 — The Growing Codex (retention hook #6: collection pull)

## Why

Hook #6 from docs/research/retention-hooks-2026-08-23.md: collection
completion made visible where it's earned. The Codex (71 entries: 39 enemies,
32 relics — verified full roster coverage) is the game's ember sink, but its
completion count only appears inside the Ledger and the Codex screen itself.
The moment the collection actually GROWS — a run producing a first sighting
or first felling — said nothing about it.

## What

One micro-line on the summary, directly under the firsts line, only when this
run produced a first (win or loss — records grow either way):

> Their tales wait in the Codex — N of M unsealed.

- `N = meta.ownedCodex.length`, `M = codexEntries.length` — live values, never
  hardcoded.
- Key `codex-pull-line`; same `EmberText.micro` / `textDim` treatment as the
  firsts line so it reads as part of the record, not a promotion.
- Gated on `_firstsLine(c) != null` — the exact moment a new tale becomes
  relevant. No firsts, no line.

## Charter fit (§Ethics)

- Factual count, zero urgency vocabulary (sweep clean).
- No button, no navigation, no price talk — the Ledger holds the door.
- Codex entries cost embers (in-game, earned), not money; this is not a
  purchase prompt, and it renders on losses only because the record itself
  grows on losses ("no delve is ever for nothing").

## Tests / verification

- test/enemy_record_test.dart: fresh-profile run asserts the line's exact
  text against live meta; a veteran profile (all enemies met+felled) asserts
  both firsts line and pull line stay absent.
- Plates: tool/codex_pull_visual_test.dart → build/codex_pull_visual/
  (small 360x640 / phone 412x915 / tablet 800x1280) reviewed clean; wraps to
  two centered lines at 360dp.
