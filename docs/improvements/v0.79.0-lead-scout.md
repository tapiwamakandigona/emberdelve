# v0.79.0 lead scout — The Settled Score

## Finding

v0.78.0 names the old foe in the Ledger but nothing ever ACKNOWLEDGES the
payoff — the run where the player finally fells the enemy that has ended
more delves than any other. The revenge hook is only half-built: a named
score with no settling. One gold summary line closes the loop.

## The improvement (one)

When a run fells the CURRENT old foe for the first time since that enemy
could be settled, the summary carries one gold line: 'The score with
<Name> is settled.' Once per foe, ever (`meta.settledFoes` set) — a payoff,
not a recurring pat on the head; an early-band foe would otherwise fire
the line on nearly every run (noise, not payoff).

## Mechanics

- `oldFoe` moves from ledger_screen.dart to meta.dart (controller needs it;
  UI already imports meta). Same semantics, same tests.
- Controller transient `pendingSettledFoe` set at the felled-record site in
  recordCombatStats when felledId == oldFoe(meta).id and not yet settled;
  survives mid-run resume via the autosave side channel (run_new_tracks
  pattern); cleared in startRun and endToTitle.
- `settledFoes` persists (sorted list JSON, cloud merge union).

## Rejected

- Fire every time the old foe is felled — noise for early-band foes.
- Reopen the score when the foe fells you again — a see-saw that turns a
  payoff into a treadmill; §Ethics (no manufactured recurring obligation).
- Reward embers for settling — the moment is the reward; paying it cheapens
  it and invites farming.
- Taunt/gloat copy — the Ledger states; so does the summary.
