# v0.9.0 "Today's Trials" — design (draft 2026-08-16)

## Why (studio-priorities lesson 2)
Daily goals extend sessions and create a return-moment without streak
pressure. Emberdelve already has the Daily Delve (fixed seed per date) and
the Weekly Delve (one mutator per week). The gap: the daily is *the same
kind of run every day* — same rules, only the seed changes. Rotation of the
RULE, not just the layout, is what makes "what's today's?" a genuine
curiosity hook (Wordle's fixed rule works because the puzzle content is the
variety; our variety must come from the trial itself).

## What ships
Each calendar date deterministically carries ONE **trial** on top of the
Daily Delve seed — no server, no streaks, no expiry language (§Ethics).
A trial is either:
- a **mutator day**: one existing mutator id applied to the daily run
  (`all_d4`, `elites_only`, `no_shops`), or
- a **goal day**: vanilla rules plus a declared bonus objective judged from
  the run result (pure function over the final sim snapshot + RunTrace),
  e.g. "finish with 40+ gold", "win 4+ fights", "reach floor 5 untouched".

Goal days pay a small ember bonus when met (banked via the normal path, no
new currency). Missing the goal costs nothing and says nothing — the result
line reads "Trial met" / silent otherwise. Banned-words sweep applies.

## Determinism
`lib/sim/daily.dart` stays sealed and untouched. New pure module
`lib/game/trials.dart` (game layer, NOT sim — the sim never learns about
trials; mutator days reuse the existing `cmd['mutators']` seam):

```dart
TrialDef trialForDate(int year, int month, int day)
```
- derive `hashDomainString('emberdelve-trial:$y-$m-$d')`
- index into `trialsOrder` (authoring order, append-only, same convention
  as mutatorsOrder)
- trial catalog as data in `lib/data/trials.dart` (id, name, blurb,
  mutators list, goal predicate id + params, ember bonus)

Goal predicates are pure functions `(Map snapshot, RunTrace trace) -> bool`
keyed by id — forward-compatible: unknown ids = no goal (old saves safe).

## UI
- Title screen daily card: one extra line — trial name + blurb (existing
  card, ValueKey `daily-trial-line`).
- Summary screen for a daily run: "Trial met ✦ +N embers" chip when
  achieved (ValueKey `trial-met-chip`), nothing when not.
- Daily share text: append trial name after the header so shared results
  carry the rule ("Emberdelve Daily — 2026-08-16 · Flint Day").

## Tests
- trialForDate determinism + distribution sweep (every date 2026–2028 maps
  to a valid catalog entry; rough uniformity).
- Each goal predicate: met/not-met fixtures from real sim snapshots.
- Controller e2e: daily with mutator day actually applies the mutator;
  goal day banks the bonus exactly once (idempotent on resume).
- Share text honesty + banned-words sweep extended to trial blurbs.
- No-trial-catalog-drift test: every trial's mutators are `isKnownMutator`.

## Non-goals
- No new sim behavior, no simVersion bump (mutator days ride the existing
  seam; goal days are pure observation).
- No streak counters, no "you missed yesterday" surfaces of any kind.
