# v0.174.0 lead scout — The Honest Fold (scroll-comfort pass)

Owner directive (2026-08-31 18:45): "improve the ui a lot. I don't know if
people like having to scroll at all in any part of the app... you know
what's best."

Audit verdict: scrolling itself is HEALTHY here — CTAs are already pinned
outside the scroll (shop's Leave button, roster's back), list screens
(codex 117 entries, provings 22, roster 14) cannot honestly fit a fold,
and in-run screens only scroll on short phones as an overflow guard.
The real gap: ZERO scroll affordance anywhere — no scrollbar, no fade —
so a player has no way to know the Wardrobe waits under 14 delver cards.

Chosen: ScrollComfort — a reusable edge-fade shell (lib/ui/widgets.dart).
Bottom fade while content waits below, top fade once content is scrolled
past, neither when everything fits. Listens to the child scrollable's own
notifications (owns no controller, changes no physics); vertical axis only
(wardrobe chip rows unaffected); IgnorePointer (visual only); fades to
EmberColors.bg so it reads as the room's darkness.

Applied to: roster, ledger, codex, provings, news, credits, settings,
shop, title, summary. Combat/map untouched (they scale, not scroll).

Considered and rejected:
- Removing scrolling via pagination/tabs: dishonest fit — 117 codex
  entries in a pager is WORSE navigation, and Flutter's own guidance
  favors affordance over pagination on mobile.
- Material Scrollbar chrome: fights the de-Flutter art direction.

Verified: 3-test scroll_comfort_test (on/off/tap-through) + plates
(tool/honest_fold_visual_test.dart) at 412x915.
