# v0.67.0 lead scout — The Dyed Delver (per-delver worn dyes)

Date: 2026-08-26. Scout ran after v0.66.0 (The Dressed Delver) closed.

## The lead

Dyes are the LAST wardrobe selection still global: `MetaState.activeDye` is one
string, so buying a violet dye repaints the Kindler, the Warden, the hearth —
everyone. v0.66.0 just fixed the identical defect for epithets, and the first
outside player ask ("You could add character customisation", 2026-08-23 review)
is answered better when each delver keeps their own coat. The hearth on the
title screen becomes the visible payoff: five delvers around the fire, each in
their own dye.

## Shape (mirror v0.66.0 exactly — pattern already proven)

- `MetaState.charDye` (charId → dye id), `dyeFor(charId)` falling back to
  legacy `activeDye`, which is never written again. `_dyeMap` fromJson
  validator (known character AND known dye, same as `_epithetMap`).
- Cloud merge: fresher side wholesale (same convention as charEpithet).
- `setActiveDye(id, {required forChar})` — guards ownedDyes +
  unlockedCharacters. OWNERSHIP stays global (embers buy the dye once,
  every delver may wear it) — only the WEARING is per-delver.
- Render sites move to `dyeFor`: combat stage (`_characterId`), map marker
  (`characterId`), picker card (per delver id), title hearth (per sprite id —
  each hearth delver in their own dye), dye-card swatch (the dress target
  wearing the candidate dye, replacing the fixed defaultCharacter swatch).
- THE WARDROBE section gains the same chip row as THE EPITHET, sharing the
  one `dressTarget` state (switching in either section switches both — one
  delver is "being dressed"). Chip keys prefixed `dye-dress-` to avoid
  duplicate-key collisions with the epithet row's `dress-`.

## Rejected alternatives

- Per-delver dye OWNERSHIP (buy per delver): rejected — multiplies prices,
  reads as a paywall, violates the "real prices up front, no squeeze" charter.
- Separate dressTarget per section: rejected — two selectors on one screen
  dressing different delvers is confusing; one target is one mental model.
- Migrating `activeDye` into charDye at load: rejected — same reasoning as
  v0.66.0: fallback keeps old saves byte-stable and honors the old choice on
  every delver until the player re-dresses.

## Risk

Zero sim movement, zero save-format breakage (new optional key; absent key =
legacy behavior). Test pins to update: attire_test (setActiveDye call shape),
tool/wardrobe_visual_test. v0.60.0 picker exact-text pins unaffected (dye is a
ColorFilter, not text).
