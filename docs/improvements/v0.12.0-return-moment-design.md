# v0.12.0 — "New Embers" return-moment content drop (design)

One improvement (DEMAND): a content batch that gives lapsed players a reason
to return, sized by what v0.8–v0.11 taught us. GitHub-only release.

## Why this batch, why now

- v0.11's Ledger surfaces per-enemy records — every UNMET enemy is now a
  visible goal ("Not yet met."). New enemies plug straight into an existing
  return loop instead of needing new UI.
- v0.9's Trials rotate over the mutator catalog (mod 7); v0.8's share trace
  and v0.10's tips need no content. So the drop is enemies + events + relics,
  no new systems.

## Scope (current roster: 25 regulars/elites + 6 bosses, 27 relics, 33 events)

- 4 regular enemies: 2 early band (fromLayer 2), 2 late band (fromLayer 5).
- 1 elite (the 8th).
- 0 bosses. HARD CONSTRAINT: bossForSeed = seed % count; golden anchor
  20260723 % 6 == 1 (ember_tyrant). 20260723 % 7 == 0, % 8 == 3 — any new
  boss breaks the anchor mapping. Bosses stay at 6 this release.
- 3 events, 4 relics — themed with the new enemies.
- All new copy through the banned-words check (§Ethics).

## Sim consequences — deliberate, not casual

Adding to `enemiesOrder` changes `_regularsFor/_elitesFor` pool lengths, so
every `rng.range(1, pool.length)` pick shifts: ALL bossGoldens + goldenV6
re-anchor. Documented policy (test/sim_test.dart header): re-pin every value
from a REAL build's printed hashes — never hand-edit one to green — and log
old -> new in progress.md. v0.5.0 precedent: bossAnchorSeeds 20260722..27.

- Append new ids at the END of their band comments in enemiesOrder; never
  reorder existing ids.
- No simVersion bump: save format unchanged (v0.6.0 difficulty precedent —
  bump only for snapshot shape changes, not pool contents).
- content_test guards (enemy/relic/event counts) updated in the same commit.
