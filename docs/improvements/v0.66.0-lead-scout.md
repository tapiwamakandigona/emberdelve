# v0.66.0 lead scout — "The Dressed Delver" (per-delver worn epithets)

## Decision
Per-delver worn epithets, chosen. The wardrobe's THE EPITHET shelf becomes
delver-aware; each delver wears their own title.

## Why this lead
- Direct answer to the 08-23 review ask ("You could add character
  customisation") with systems we already have — zero new art, zero sim.
- Completes the per-delver identity arc: v0.60 tally → v0.65 charted depth →
  v0.66 worn title. The picker card becomes a portrait of THAT delver.
- Epithets are earned-only (§Ethics-clean); dressing them per delver adds
  expression without adding any purchase or pressure surface.

## Rejected alternates (this scout)
- Provings-shelf whisper: title already carries "The Provings — N of 10
  cleared"; a second pointer is a nag.
- Eleventh proving: DEAD, not just held — the_proven target is test-pinned
  to provings.length, so an 11th proving retroactively strips the epithet
  from players who cleared all ten. Un-earning is an ethics violation.
  Any future proving needs a redesigned promise first.

## Design cut
- **Data**: `Map<String, String> charEpithet` on MetaState (delver id →
  epithet id). Absent key = falls back to legacy `selectedEpithet` (the
  pre-v0.66 choice keeps being honored everywhere; no seeding pass, no
  save-size cost for players who never dress anyone).
- **Resolver**: `String epithetFor(MetaState m, String charId)` =>
  `m.charEpithet[charId] ?? m.selectedEpithet`. Every read surface goes
  through it: picker card line, summary epithet, share card ×2, run-record
  'epithet' banking (worn by the RUN's character at bank time).
- **UI**: a delver chip row (unlocked delvers, portrait + name) sits at the
  top of THE EPITHET section; the WORN tag and tap-to-wear act on the
  chip-selected delver. Default chip = last delved (fallback kindler).
  Chip row hidden with only one delver unlocked (fresh installs see the
  shelf exactly as today).
- **selectEpithet(id)** gains the target delver; legacy setter semantics
  (set selectedEpithet) retire — writing charEpithet[target] instead.
  `selectedEpithet` stays as decode-time fallback only; never written again.
- **Cloud merge**: cosmetic-selection convention — fresh side's map
  wholesale (same rule as selectedEpithet/activeDye today).
- **Save format**: charEpithet omitted when empty; decode drops unknown
  epithet ids and unknown delver ids (same hygiene as provingsCleared).

## Gate plan
- Tests: resolver fallback truth table; wear/isolation (dress warden, kindler
  unchanged); locked-epithet refusal per delver; round-trip; merge; run
  record banks the run character's worn title; picker shows per-delver line.
- Existing epithet tests keep passing where they assert unlock logic; WORN
  placement tests updated to chip context.
- Plates: wardrobe with chip row at 360/320 (longest name "the Well-Oiled"
  under widest chip row), picker with two delvers wearing different titles,
  fresh install unchanged.
- Zero sim movement; save format additive.
